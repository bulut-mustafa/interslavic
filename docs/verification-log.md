# Verification log

Every load-bearing claim in the plan, with how it was checked. Written because a
vacuous test assertion was found in the suite, which made "the tests pass" an
inadequate answer to "is this correct?".

**Three categories, kept strictly separate:**
`VERIFIED` = checked empirically in this repo · `CORRECTED` = was wrong, now fixed ·
`UNVERIFIED` = sourced from research only, **not** independently confirmed.

Date: 2026-10-18.

---

## A second engine to check against (2026-10-18)

Until now every form we emit was generated by one library and checked against a
full-form index built by **that same library** - which cannot catch a paradigm that is
wrong in the same way twice. `docs/morphology-coverage.md` admitted this: the audit
"validated the library largely against itself, with only four forms hand-derived".

There is now an independent one. **`@interslavic/utils` 3.4.4 (MIT)** is the inflection
and transliteration engine behind **interslavic-dictionary.com** - so it is literally the
table a user sees when they check our output against the dictionary site.

Two honest caveats, both load-bearing:

- It is **deprecated on npm**: *"Superseded by @interslavic/morphology, @interslavic/translit,
  @interslavic/conllu, @interslavic/levenshtein, @interslavic/stemmer"*. The package we
  depend on is its designated successor, not an unproven alternative.
- Both come from the same authors, so they are **not fully independent**. They are
  independent *implementations*, which is enough to catch a coding error, and not enough
  to catch a shared misreading of the grammar. Tier-1 pages still decide.

It is used as a **tier-3 oracle only**: where it disagrees with the normative pages, the
pages win, and the disagreement is written down here.

### Orthography: all four variants now byte-identical to the reference

`packages/eval/scripts/diff-orthography.ts` renders every generated form in all four
orthographies and compares against the official transliterator.

| Variant | Before | After |
|---|---|---|
| standard | **0** / 348,707 | 0 |
| cyrillic | 8,097 / 348,707 | **0** |
| etymological | 12,532 / 348,707 | **0** mismatched, 12,532 *sanctioned variants* |
| simplified | no official tag to compare against | confirmed = standard with jat folded |

**The Cyrillic defect was real, and it was ours.** We wrote `pisańje` as `писање`; the
orthography page calls `писанје` the ideal and `писање` only a *"valid alternative"*,
allowed because *"automated transliteration is unable to predict whether nj should become
њ or нј"*. The etymological spelling **is** that prediction - `ń` marks precisely the case
where the `j` begins a suffix - so we were taking a fallback we are not entitled to. Now
fixed for all 8,097 forms, with the page's second two-sound case (a `j` after a Latin or
Greek prefix: `konjunktura` → `конјунктура`) handled by the same rule.

The reference implementation carries that prefix list too (`konjug`, `konjun`, `injek`)
and is **missing `panjev`**, which the page names explicitly. So `panjevrějsky` →
`панјеврєјскы` is a case where we are right and the dictionary site is wrong.

The 12,532 etymological differences are **not defects**: the page says t́ and d́
*"may be written with a haček as well: ť and ď [...] Likewise, ĺ can be written as ľ"*.
We emit the haček forms because they are single codepoints, which keeps output font-safe
and byte-stable. Recorded as a choice, not a divergence.

`simplified` is not ours to invent either, and we did not: *"the best alternative is
Latin e / Cyrillic е. This is a legitimate simplification"*. The same page offers a second
one we deliberately do **not** apply - `y` → `i`, addressed to those "targeting a
predominantly South Slavic audience" rather than to everyone.

### Paradigms: the forms were already right

`packages/eval/scripts/diff-paradigms.ts` compares **the form the engine would emit** for
a feature slot - `realize()` output, not a raw paradigm dump, so variant preference and
syncretism tie-breaks are included - against the same slot in the reference.

| Class | Slots | Agreement |
|---|---|---|
| noun (7 cases × 2 numbers) | 122,878 | **99.19%** |
| verb, present tense | 26,118 | **100.00%** |
| verb, l-participle | 4,353 | **100.00%** |

This answers the question that started the audit: **our divergence from other tools is not
in the forms.**

### The one real defect it found: plurale tantum never inflected

The library tags `dveri` "door", `usta`, `nožnicy` with `Number=Ptan`, which matches
neither `Sing` nor `Plur`. `selectForm` matched features exactly, so **all 155
plurale-tantum entries failed to inflect in every case** and silently fell back to the
citation form. A plurale tantum has no number to choose between, so a requested `Number`
is not a constraint it can fail; `selectForm` now says so. 854 slots recovered.

**The full-form validator could not have caught this**, for the same reason it missed
`Kak ty dělaješ?`: the citation form it fell back to is a real word.

### The remaining 136 noun slots: we are right, the reference is wrong

136 slots across **17 lemmas**, every one of them a word where the dictionary states
explicit principal parts - `Ljviv (Ljvova)`, `plȯť (plti)`, `dȯći (dȯćere)`.

Checked before concluding anything: `declensionNoun` returns **identical output with and
without the `addition` argument**, so the reference ignores the dictionary's own editorial
override. We feed it to the morphology library as principal parts, which is why we differ.

Confirmed at tier 1 for `dȯći`, from the noun page: *"feminine nouns on -i/-er-,
containing only two nouns: mati 'mother' and doči 'daughter'"*, and *"mati is inflected
like kost: gen./dat. materi"*. So gen.sg is `dočeri` - **ours** - and not the reference's
`doče`. `dno` Voc.Sg is a second clear case: we give `dno`, the reference gives
`den / dnju` for the vocative of a neuter noun.

## Reflexives: `se` and `svoj` (2026-10-18)

Both rules are stated outright on the pronouns page and neither was built:

> "Se is used in reflexive verbs: *Ja myju se* 'I'm washing myself'. If it needs to be
> stressed, the longer form is used: *Ja myju jedino sebe*. After a preposition, it is
> better to use the longer forms: *k mně*, *za tebe*."

> "Whenever the possessor is also the subject of the sentence, the reflexive *svoj* is
> used, no matter whether this subject is in the third person or not: *Ja myju svoje avto*."

| Source | Was | Now |
|---|---|---|
| "He hurt himself." | `On zabolěl **sebe**.` (the stressed form) | **`On zabolěl se.`** |
| "I wash myself." | `Ja peru **myself**.` (raw English) | **`Ja peru se.`** |
| "I am washing my car." | `Ja peru **moj** voz.` | **`Ja peru svoj voz.`** |
| "He gave her his book." | — | **`On dal ... svoju knigu.`** |

`myself` is the one reflexive the dictionary's gloss list for `sebe` omits ("oneself,
yourself, himself, herself, itself, ourselves, yourselves, themselves"), which is why it
alone came through as raw English; the others resolved to `sebe` but to the **stressed**
form where the clitic belongs.

English does not distinguish "his [own]" from "his [someone else's]", so the third-person
`svoj` decision names the alternative in the gloss (`jegov`/`jejin`/`jihny`) rather than
pretending the choice was free of doubt.

### A silent realisation failure behind it

Asking for the clitic did nothing at first, and the reason generalises: **`sebe` has no
`Number` feature at all** - one form serves singular and plural - so requesting
`Number=Sing` matched nothing and realisation fell back to the citation form. That
fallback *looked* like a correct answer and was not a decision at all.

`selectForm` now drops a requested feature that **no token in the paradigm defines**,
because a feature the lexeme does not distinguish cannot select among its forms. Keys that
the paradigm does use still fail loudly, so this does not mask a real mismatch. It is the
same class of bug as the plurale tantum one, found by the same reasoning.

### A vacuous assertion, caught by the audit

The negative test ("don't use `svoj` when the possessor is not the subject") **survived**
its mutation. Under the mutation the output is `Svoj brat imaje dvoh synov.` - capitalised,
because the possessive is sentence-initial - and `toContain('svoj')` is case-sensitive, so
the assertion passed while the rule was entirely disabled. Now compared in lower case, with
a positive assertion (`moj brat`) alongside the negative one.

This is the second vacuous assertion mutation testing has caught in this project, and the
reason the log exists.

### One mutation that could never have applied

The mutation written for that rule used `\n` in a `sed` replacement, which **BSD sed does
not expand** - it would have produced a syntax error rather than a behaviour change, and
been counted as a kill for the wrong reason. Rewritten as a single-line substitution and
verified to apply and be killed. A grep now confirms no remaining mutation depends on `\n`.

## Word sense: rejected on a flawed measurement, then shipped (2026-10-18)

This one is recorded in two parts, because **the first measurement was wrong and the
conclusion drawn from it was wrong.**

### The defect

The dictionary marks narrower senses with a parenthesised label - `prati` is
*"wash (clothes), launder"* while `myti` is plain *"wash"* - but `normalizeGloss`
**deletes every parenthetical** before indexing. Both became the key `wash`, and frequency
(5365 vs 5221) handed every "wash" to the laundry verb. 412 bare gloss keys have a
labelled and an unlabelled sense competing this way.

### First measurement, and why it was wrong

Two candidate rules were simulated over the dictionary:

| Rule | Winners changed | First verdict |
|---|---|---|
| flat +8 penalty on a labelled sense | 119 | rejected |
| 25% frequency discount | 34 | rejected |

Both looked like 60/40 improvements - `wash`→`myti` and `cup`→`čaša` good, but
`note`→`zapisati` (a verb), `youth`→`mlådežny` (an adjective), `record`→`naigrati` (a verb)
bad - so the idea was written off.

**The simulation was POS-blind.** `compareEntries` penalises a part-of-speech mismatch by
**+1000**, which dominates every other term, so a noun source word never competes against a
verb candidate in the first place. Half the "regressions" could not occur.

### Second measurement, with part of speech held constant

30 flips, and the quality is not 60/40 at all:

- **better:** `wash`→`myti`, `flood`→`potop` (was "flood of tears"), `leave`→`ostaviti`
  (was "leave by transport"), `reservation`→`rezervacija` (was a nature reserve),
  `sketch`→`skica` (was a comedy sketch), `relief`→`oblėgčeńje` (was the artwork),
  `medicine`→`lěk`, `cup`→`čaša` (was a sport trophy), `knight`→`rycaŕ` (was the chess
  piece), `disorder`→`neporędȯk`, `draft`→`skica`
- **neutral:** `pawn`, `record`, `term`, `subject`, `shaft`, `whistle`, `swear`, `cast`
- **worse: exactly one** - `doctor`→`lěkaŕka`, a *female* doctor

### The one regression had its own cause, and its own documented fix

`lěkaŕka` ("doctor", f.) competes with `lěkaŕ` ("physician, doctor", m.anim.) on equal
terms. The word-formation page is explicit about what these forms are:

> "The female equivalent of the endings -nik and -ec is -nica and -ica respectively [...]
> In other cases, we rather use the ending **-ka for female equivalents of male persons**:
> *prijatelj* 'friend' > *prijateljka* 'girl friend'"

So the masculine is the base and the feminine is the marked member. English "doctor" and
"teacher" mark no gender, so they should select the base.

**The test has to be narrow.** A blanket "prefer masculine over feminine" was measured and
is badly wrong - it would give `gad` for "snake" instead of `zmija`, `načeľnik` for "head"
instead of `glåva`, `krasavėc` for "beauty" instead of `krasa`. What ships demotes a
feminine candidate **only when it is derivable from a masculine candidate that is actually
present**, by the page's own suffix rules including the documented consonant change
(`k/c > č`, `g > ž`, `h > š` before `-ka`). That is 104 gloss keys, and it changes 5
winners, all of them correctly: `blonde`→`blondin`, `bore`→`dȯlgočasnik`,
`cosmetician`/`beautician`→`kosmetik`, `successful person`→`uspěšnik`.

With both rules in place, `doctor` resolves to `doktor` again - the regression is gone.

### What shipped

- A **frequency discount, not a point penalty.** It must be a discount because frequency is
  only consulted when scores tie, so one penalty point would override a 10,000-point
  frequency gap. That is precisely why the flat penalty flipped 119 keys.
- A label is discounted **only when the source does not support it**. The sentence's content
  words are now passed into the ranker, so the label is treated as evidence rather than as
  a liability:

| Source | Result |
|---|---|
| "I wash **myself**." | **`Ja myju se.`** - no support for "(clothes)", so the general verb |
| "I wash the **clothes**." | **`Ja peru odědžu.`** - "clothes" supports the label, so the laundry verb |
| "I see the flood." | **`potop`**, not `potok` ("flood of tears") |
| "Give me a cup." | **`čašu`**, not `kubȯk` (a sport trophy) |
| "He is a doctor." | **`doktor`** - unchanged, the discount does not override a clear frequency gap |

Gold went 11/29 → **12/29**: g23 "I'm washing myself" now reproduces `Ja myju se` exactly,
and the stale-classification guard in the gold suite is what reported it.

**The lesson worth keeping:** a measurement that omits the dominant term in the scoring
function will mis-rank every alternative. The first conclusion here was not conservative,
it was simply wrong, and shipping nothing would have left a defect in place on the strength
of a bad simulation.

## A conflict inside the normative source (2026-10-18)

Gold g13 expects `svoje **ključi**`; we emit `svoje **ključe**`, and so does the reference
engine. Checked rather than assumed, and the grammar's own noun page settles it against the
gold sentence:

> "Animate nouns have the nominative plural ending **-i** instead of the ending **-y/-e**
> of inanimate nouns."

with the table giving inanimate soft `kraj` → nom./acc. pl. `kraje`. `ključ` is `m.`
(inanimate) in the dictionary, so `ključe` is table-conformant. `ključi` appears **once**
on the whole site, in that one syntax-page example, and in no paradigm table.

So this is a disagreement between the author's paradigm table and the author's example
sentence - not a defect of ours. Recorded on the gold pair itself so nobody "fixes" the
engine to match it.

## Modals: the worst output the engine produced (2026-10-18)

A modal is tagged `AUX` by the parser, and `needsVerbFeatures` tested only for `VERB` and
a copula. So a modal received **no verb features at all** - no person, tense, mood or
VerbForm - and was realised by the longest-form tie-break, while its complement, a bare
infinitive with no `to` to recognise it by, was conjugated as a finite verb.

| Source | Was | Now |
|---|---|---|
| "I can swim." | `Ja **možeše plavaju**.` (an imperfect 3sg) | **`Ja mogu plavati.`** |
| "I could swim." | `Ja **could** plavaju.` (raw English) | **`Ja mogl plavati.`** |
| "He must go." | `On **imaju** ide.` (*imati* = to have) | **`On musi idti.`** |
| "She should read." | `Ona **dolžnogo** čitaje.` (a genitive adjective) | unchanged - see below |
| "We can read." | — | **`My možemo čitati.`** |
| "Father could not find his keys." | — | **`Otec ne mogl nahoditi...`** |

Modals are among the most common things a learner writes, so this was the single largest
accuracy hole in the engine, and raw English in the output is the most damaging form of
wrongness there is: it cannot be mistaken for Interslavic, but it also cannot be trusted.

Four separate causes, each fixed:

1. **No verb features.** A modal is now included in `needsVerbFeatures`.
2. **Complement conjugated.** The infinitive-complement test required a `mark` child
   ("want TO go"), which a modal complement never has. The complement of a modal is now
   an infinitive by rule.
3. **Tense lost.** English marks tense on the modal itself, and Stanza gives `could` no
   `Tense` feature at all, so the plan supplies it: can/may → present, could/might → past.
4. **Person read off the wrong token.** UD hangs the subject off the *main verb*, not the
   modal, so `subjectPerson` found none and defaulted to 3rd singular - "we can" came out
   singular. Person and number now come from the subject of the verb the modal governs.

Negation also had to retarget: `ne` goes before the finite verb, which with a modal **is**
the modal - `Otec ne mogl najdti`, not `Otec mogl ne najdti`.

### Why these are curated, and how "must" was decided

The dictionary marks the right verbs **`v.aux.`** - its own category for auxiliaries - so
the data was always there; ranking simply got it wrong, because `iměti, imati` ("have,
possess", frequency 6214) also carries the gloss "must, have to" and outranked the real
modal. Modals are a tiny closed class used constantly, which is exactly the argument
already made for `function-words.json`, so they are curated with cited evidence rather
than ranked.

`musěti` over `morati` was decided on **the dictionary's own `intelligibility` column** -
a field this project had never read:

| | positive in | negative in |
|---|---|---|
| `musěti` | be, cs, hr, pl, sk, uk (**6**) | bg, ru, sr |
| `morati` | hr, sr (**2**) | be, bg, cs, pl, ru, sk, uk |

This is the first use of that column, and it decided a real choice that frequency would
have got wrong. It is direct evidence for reading the other ignored per-language fields.

### Deliberately left broken

`should`, `ought to`, `would` and `shall` are **not** in the table. Their natural
Interslavic needs the conditional (`by` + l-participle) or the predicate adjective
`dȯlžny`, neither of which is built. Guessing a finite verb for them would produce
confident nonsense, so they keep falling through to ordinary lookup and stay visible as a
defect. `UNHANDLED_MODALS` names them, and a test asserts they are absent, so adding one
by accident fails the suite.

## Measuring meaning on 29 pairs instead of 10 (2026-10-18)

The gold set was 10 sentences from a single page, and it had done its job - it caught five
grammar bugs that 135 passing tests had not. But a 10-sentence set drawn from one page
measures one page's worth of grammar, and it reported 6/10 while the engine could not form
a question, a passive, a reflexive, a purpose clause or a comparative at all.

It now has **29 pairs from six pages** (syntax, prepositions, verbs, pronouns, adjectives,
numerals), every `isv` string checked against the page text character by character, each
carrying its page and the constructions it exercises. The new ones deliberately cover what
the syntax page never exercised: the preposition case contrast (`pod stolom` vs `pod stol`),
reflexive `se`, possessive `svoj`, predicate short-form adjectives, numeral government and
plurale tantum, purpose clauses and the optative.

**The honest score is 10/29.** That is not a regression from 6/10 - it is a wider ruler.

Terminal punctuation is no longer compared: several pages give their examples inline, with
no final period, so requiring one would measure punctuation instead of translation. That
punctuation is carried over at all is asserted separately.

### Every difference is now classified, not excused

The old harness had a free-text exception list keyed by the Interslavic string. With 19
differences that does not scale, and "accepted" blurred three very different things. Each
difference now carries a status, and the suite fails if one is missing, if one is stale
(the pair has started matching), or if the tally of statuses changes without being updated
- so quietly reclassifying a defect as "acceptable" cannot pass:

| Status | Count | Meaning |
|---|---|---|
| `acceptable` | 3 | a documented equivalent; the grammar permits both |
| `defect` | 11 | we are wrong, and the cause is named |
| `unsupported` | 4 | the construction is not built yet |
| `parser` | 1 | the UD parse is wrong, so transfer never had a chance |

That last category earned its place. For "Which woman does that man love?" Stanza makes
**`does` the root VERB** with `love` as its `xcomp`, so do-support is never recognised and
we faithfully translate a wrong parse. Before writing it off, five comparable questions
were checked - "Does he know the answer?", "What does she want?", "Which book does she
read?", "Do you know the answer?", "Where does father live?" - and **all five parse
correctly**. So this is an isolated parse error, not a systemic one, and a parse-repair
heuristic would be unjustified.

`packages/eval/scripts/score-gold.ts` prints the full report with a per-construction pass
rate, so a change shows *which* rule improved rather than only moving a single number.

## Coordination: a wrong case in an entirely ordinary sentence (2026-10-18)

`conj` was not in the case cascade, so **every coordinated noun fell through to the
nominative fallback**. This is not an exotic construction:

| Source | Was | Now |
|---|---|---|
| "I see a dog and a cat." | `Ja vidžu psa i **kot**.` | **`Ja vidžu psa i kota.`** |
| "He works in the house and the garden." | `…v domu i **sad**.` | **`On rabotaje v domu i sadu.`** |
| "I help my brother and my sister." | — | **`Ja pomagaju mojemu bratu i mojej sestrě.`** |

The first conjunct was right and the second wrong, in the same phrase - exactly the kind of
difference a Slavic reader notices at once and the full-form validator cannot see, because
`kot` is a real word (the nominative of the word we wanted).

**This required no new Interslavic rule.** A conjunct shares its head's grammatical role,
so `case.coordination` re-uses the head's decision *and its confidence* - a conjunct must
not claim more certainty than the `obj`→Acc default it is copying. That is a fact about the
UD annotation, not a claim about Interslavic, so it needs no grammar citation.

Two propagation paths were needed, because UD hangs every conjunct off the **first** one:

- a preposition governs the whole coordination, not just its first member, so the governed
  case propagates transitively (the preposition itself is still emitted once);
- verb government propagates the same way, which is why both conjuncts of "help" are dative
  and both possessives agree into the dative with them.

`obl`, `nmod`, `advmod` and the rest still reach the fallback. That is deliberate: a bare
oblique's case depends on meaning the grammar does not state case by case, so it stays a
visible `guess` rather than an invented rule.

## Verb government, wired in at last (2026-10-18)

`resolveCase` has accepted a `verbGoverns` argument since Russian support was added and **nothing ever supplied
it**, so `byVerbGovernance` was unreachable and every direct object fell through to the
`default`-confidence accusative. The data to populate it was already parsed and sitting
unused in `AdditionInfo.governs`.

Counted directly in the dictionary: **78 verb entries carry a `(+N)` code**, of which
**33 have a preposition inside the lemma** (`obhoditi sę bez (+2)`, `obraćati sę k (+3)`)
where the code states what the *preposition* governs, not the verb. That leaves **45 true
verb-government entries**: Dat 20, Ins 16, Gen 9.

They are exactly the verbs an English speaker gets wrong by analogy:

| Source | Was | Now |
|---|---|---|
| "I help my brother." | `Ja pomagaju mojego brata` (acc) | **`Ja pomagaju mojemu bratu.`** (dat) |
| "I avoid the question." | `…pytanje` (acc) | **`Ja izběgaju pytanja.`** (gen) |

Note the second-order effect: `mojemu` follows the object into the dative through
agreement, which a governed case that agreement ignored would have left as `mojego bratu`.

Three confirmations that this is attested and not inferred:

- The codes are the dictionary's own, in the same numeric scheme already verified for
  prepositions (`(+2)`=Gen … `(+6)`=Loc), so the gloss cites them:
  *"pomagati" governs this case lexically - the dictionary marks it (+3)*.
- `pomagati` +Dat and `vladati` +Ins were both on the earlier **UNVERIFIED** research list
  (`bojati sę`+Gen, `pomagati`+Dat, `upravjati`+Ins). Two of the three are now attested in
  the data. `bojati sę` carries no code, so it stays unimplemented.
- A verb with no code keeps the honest `default` accusative: "They thank the teacher"
  selects `blagodariti`, which has no code, and stays `Acc (default)`.

Confidence is `high`, not `certain`: the code is read off the entry the ranker chose, and
a different lexeme would carry a different code. The government pre-pass and the main
lexical pass therefore share one `rankedFor()` helper, so they cannot drift about *which*
verb was chosen.

### Mutation coverage for the new rules

Eighteen mutations were added and all eighteen are killed: six for modal verbs, three for
verb government (pre-pass disabled, government read off the subject instead of the object,
citation dropped), four for coordination (rule dropped from the cascade, conjunct claiming
`certain`, conjunct inheriting from the wrong token, government not propagated), four for
the Cyrillic two-sound rule, one for the plurale tantum relaxation.
One **pre-existing mutation had to be repaired** - `"cyrillic skips the standard fold"`
no longer matched after `toCyrillic` changed, and a mutation whose pattern does not match
is counted as a survivor, so leaving it would have silently weakened the gate.

A literal `U+0001` character was also removed from two files (`orthography.ts`, and the
pre-existing one in `split-lemmas.ts`) in favour of visible `` escapes - the same
defect class this log already records fixing once, where an invisible character inside a
regex "worked by accident".

### The audit now runs in slices, because it could not run at all

The audit is ~119 suite executions, and this machine killed it twice for memory pressure -
once with the default worker pool, once with a single fork. Both times the `EXIT` trap did
its job; the first kill still left one mutation applied in `split-lemmas.ts` (`if (false)`
where `if (reflexive)` belongs), and the suite caught it on the next run.

Two changes make the gate usable rather than aspirational, and neither weakens it:

- `TEST_CMD` overrides the test command, so the same tests can run in a smaller worker pool.
  A single-threaded *threads* pool turned out to be ~3x faster than forks (20s vs 70s per
  suite run) and lighter on memory:
  `TEST_CMD="npx vitest run --silent --pool=threads --poolOptions.threads.singleThread=true"`
- `FROM`/`TO` run a slice by 1-based mutation index, so the audit can be completed in
  chunks. Each chunk still saves and restores every file it touches, and the summary
  **prints "this is a PARTIAL run"** whenever anything was skipped, so a slice cannot be
  mistaken for a full pass.

Every mutation added in this round was also verified individually against the test file
that should catch it, before being added to the script:

| Group | Mutations | Result |
|---|---|---|

### The audit's own maintenance hazard

**Three pre-existing mutations went stale in this one session**, each because a refactor
moved the line its `sed` pattern matched:

| Mutation | Broken by |
|---|---|
| `cyrillic skips the standard fold` | `toCyrillic` gaining the two-sound pre-pass |
| `government read off the wrong verb` | the conjunct-propagation rewrite of that loop |
| `frequency tie-break removed` / `frequency sorted ascending` | frequency becoming `effectiveFrequency` |

This is a real property of a `sed`-based audit, not an accident, and it cuts the right way:
the script distinguishes **"MUTATION DID NOT APPLY (pattern not found)"** from a true
survivor and counts it as a survivor anyway. A stale mutation therefore shows up as a
failure rather than as silent green, which is exactly what should happen - but it means
**every refactor of a line a mutation targets needs the mutation updated in the same
change**, and the audit has to be re-run after refactors, not only after behaviour changes.

One **pre-existing mutation had to be repaired**: `"cyrillic skips the standard fold"` no
longer matched after `toCyrillic` changed, and the script counts a mutation whose pattern
does not match as a SURVIVOR - so leaving it would have reported a false alarm while
silently covering nothing.

## The limit of self-validation (found 2026-10-17)

A user compared our output with another translator and was right to distrust ours.

**"How are you doing?" produced `Kak ty dělaješ?`** — which means *"how do you do it?"*, a
question about method. It scored **100% validated**: every word real, correctly inflected,
every case traceable to a documented rule. It was still the wrong sentence.

> **The full-form lexicon proves words are real. It says nothing about whether the sentence
> means what was asked.** Those are separate questions, and only gold data answers the second.

Interslavic for the greeting is **`Kako jesi?`** / `Kako ty jesi?` (*kako* + 2sg of *byti*);
`Kako se imaš?` is a valid Slovenian-style alternative. Ours was neither. The cause is not
grammatical: Stanza correctly makes "doing" the root, so a compositional engine faithfully
translates *do*. Greetings are idioms, and idioms are non-compositional.

### Measuring meaning: gold data

So a gold set was built from **Jan van Steenbergen's own grammar pages** - he co-authored the
language, making these the most authoritative parallel data available
(`packages/eval/data/gold-steenbergen.json`, from
<http://steen.free.fr/interslavic/syntax.html>).

First measurement: **1 of 10 exact matches.** It exposed five real grammar bugs that 135
passing tests and a 100% validation rate had not:

| Bug | Was | Gold |
|---|---|---|
| **Negative concord missing** | `Ja nikogda jem čokoladu` | `Ja nikogda **ne** jem čokoladu` |
| **`ne` placed after the verb** | `hlěb jest ne dragy` | `hlěb **ne jest** dragy` |
| **Infinitival "to" read as a preposition** | `hoču **do ide** do kina` | `hoču **idti** v kino` |
| **English perfect not perfective** | `Otec **kupoval** knigu` | `Otec **kupil** knigu` |
| **Tense not read off the auxiliary** | `Kde otec **kupoval**…` | `Kde otec **kupil**…` |

The first two change meaning or grammaticality outright. After fixing them: **6 of 10.**

A sixth bug surfaced while fixing these, caught by the existing suite: requesting a
perfective of a verb that has no perfective counterpart matched nothing, and realisation fell
back to the citation form - `Ona ne **znati** odgovor` instead of `znala`. The requested
aspect is now reconciled with the aspect the chosen lexeme actually has. **The validator
could not have caught this either: `znati` is a real word.**

### The four remaining differences, each judged

| Gold | Ours | Verdict |
|---|---|---|
| `Koju knigu kupil otec?` | `Koju knigu otec kupil?` | **Acceptable** - word order is free in Interslavic |
| `Ja ne hoču idti v kino.` | `…idti do kina.` | **Acceptable** - both express motion to a place |
| `Tuto avto ne jest drago.` | `Tutoj voz ne jest dragy.` | **Acceptable** - `voz` is also glossed "car" and is more frequent |
| `Nikto ne prijehal na zabavu.` | `Nikto ne prihodil do partije.` | **KNOWN DEFECT** - `partija` is the *political* party. Needs word-sense disambiguation. |

`packages/eval/test/gold.test.ts` enforces this: anything not on that written exception list
must match exactly, the match rate cannot fall below 6/10, and a stale excuse fails the suite
if a sentence starts matching.

### Closed-class words are now curated, not ranked

Ranking picked `tamto` for "that" because it is glossed exactly "that", while the general
demonstrative `tȯj` is glossed "this, that" and so looked like a weaker match - but `tamto`
means "that **over there**". Frequency and gloss-overlap are the wrong tools for a few dozen
constantly-used function words, so `packages/rules/data/function-words.json` holds curated
choices, each citing the source that justifies it. Open-class words stay with ranking.

## Test suite integrity

A test is only real if it fails when the behaviour breaks. So the suite was audited by
**mutation testing** (`scripts/mutation-audit.sh`): deliberately introduce a bug, confirm
the suite catches it. A surviving mutation means fake coverage.

| Run | Killed | Survived |
|---|---|---|
| First audit | 25 | 7 |
| After fixes | 35 | 0 |
| After prepositions + numerals | 52 | 0 |
| After the parser service | 68 | 0 |
| After the recheck before the web UI | **75** | **0** |

Run it yourself: `bash scripts/mutation-audit.sh`

### Defects the audit found in our own code

1. **`byti` 3sg returned `je` instead of `jest`.** The variant-preference list was
   `['Long','Short']`, so when no `Long` form existed it fell through to `Short`. Surveying
   the lexicon showed three competing patterns — `Long+Short` (1320 slots), `-+Athematic`
   (826), `-+Short` (382) — so the unmarked form must be preferred *first*. The old list
   mishandled 1,208 of 2,528 competing slots. Fixed; cross-checked against the dictionary's
   own principal parts (`byti → jest`, `dati → da`, `jesti → je`, `věděti → vě`).
2. **Invisible combining characters in source.** Unicode escape sequences (written in
   source as backslash-u-0-3-0-0) had been written as
   literal combining characters inside a regex. It worked by accident. Rewritten with
   visible escapes.
3. **Dead code.** An explicit yo→ye replacement was redundant: `normalize('NFD')` plus
   diacritic-stripping already maps `самолёт` and `самолет` to the same key. Removed.
4. **Prepositions were asked to inflect.** Indeclinables were given a `Number` feature,
   failed to inflect, and were wrongly reported `unvalidated`. They now bypass realisation.
5. **Numeral government ran after agreement**, so a numeral agreed with its noun's stale
   pre-government features — "I see one house" produced `jedne dom` instead of `jedin dom`.
   Government now precedes agreement.
6. **Numeral government forced the nominative.** The grammar's "nominative singular after 1"
   describes the citation form; "I see one house" is accusative. Only 5-and-up imposes a
   case now; 1 and 2-4 fix the number alone.
7. **Unreachable tie-break.** Across 66,697 feature slots, **0** stay ambiguous after
   variant preference, so the final tie-break never ran in production. Rather than leaving
   untested dead code, the logic was extracted into the pure exported `selectForm()` and
   tested with synthetic ties.

## What real parses exposed

Every sentence below was correct in tests but **wrong the first time it met a real parse**.
Hand-written fixtures had hidden these, because I had unconsciously written the parses the

head is now correctly locative. A single-word target is preferred where one exists; for
"city" the dictionary offers none.

### The perfective-present rule — confirmed at primary source

Fetched directly from `https://interslavic.fun/learn/grammar/verbs/`:

> "The future tense is formed by combining the future tense of the verb *byti* 'to be' with
> the infinitive. The forms are the same as if a verb with the stem **bud-** were conjugated
> in the present tense. Examples: ja **budu** dělati, ty **budeš** dělati, on/ona/ono
> **bude** dělati, my **budemo** dělati, vy **budete** dělati, oni/one **budut** dělati.
>
> Using the present tense of a perfective verb for the future (as is done in West and East
> Slavic) is **rather to be avoided, as it can easily be misunderstood by South Slavs**."

This is the justification for `aspect.tense.presImp`, our highest-impact rule, and it is now
confirmed from the grammar itself rather than relayed through a research agent.

The same page also explains the `Long`/`Short` variants our generator must choose between:
Interslavic admits a **third conjugation** formed by contracting `-aje-` sequences
(`-am, -aš, -a, -amo, -ate, -ajut`). So `davaje` (uncontracted) and `dava` (contracted) are
both legitimate; preferring the uncontracted form is a defensible, documented choice rather
than an arbitrary one.

### The en/ru asymmetry — confirmed genuine

English `boy` → `hlåpėc`; Russian `мальчик` → `hlåpčik`. This was checked because it looked
like a bug. It is not.

The dictionary's own per-language columns:

| | `hlåpėc` | `hlåpčik` |
|---|---|---|
| Ukrainian | хлопець | хлопчик |
| Polish | chłopiec | chłopczyk |
| Czech | chlapec | chlapeček |
| **Russian** | **парень** (lad) | **мальчик** (boy) |

Independently confirmed by English Wiktionary on Russian хлопец: *"Borrowed from Ukrainian
хло́пець (boy, lad), cognate to Polish chłopiec"*, defined as *"(colloquial) lad, boy"*.

So the root is native and means "boy" in Ukrainian/Polish/Czech, while Russian's reflex is
a colloquial borrowing meaning "lad" — Russian's word for a boy child is мальчик, matching
the Interslavic **diminutive**. Both of our outputs are correct for their source language.
The gloss panel now prints `matched en gloss "boy"` / `matched ru gloss "мальчик"` so this
is traceable rather than surprising.

## OPEN implementation gaps discovered during verification

1. **The library generates no future tense.** `inflect('byti')` exposes only `Pres` and
   `Past` — there are **no `bud-` forms at all**, even when the `bųdų` principal part is
   supplied. Since every future must be periphrastic, the engine must supply this one closed
   auxiliary paradigm itself. The primary source gives it exactly:
   **`budu, budeš, bude, budemo, budete, budut`** (note `budemo`, not `budem`).
   This does not contradict "author no paradigm tables": it is one documented irregular
   auxiliary, not an open class.
2. **Agreement covers `amod`/`det`/`nummod`/`appos` only.** Predicate adjectives and
   participles are not handled.
3. **Word order is copied from the source.** Fine for English and Russian SVO; a real
   precedence spec is needed before any SOV source language.
4. ~~**Verb governance is not wired in.**~~ **CLOSED 2026-10-18** for the 45 entries the
   dictionary codes; see "Verb government, wired in at last" above. Verbs with no code
   still take the `default`-confidence accusative, and hand-authoring the rest remains
   out of scope because the grammar does not state them.
5. **Predicate adjectives and participles** are not covered by agreement in general - a
   root ADJ/NOUN is special-cased, nothing else is. This is now a measured defect, not a
   suspicion: "Peter is happy" gives **`Peter jest ščestliva`** - feminine - because an
   untranslated PROPN subject carries no lexical gender for the predicate to agree with.

### Two defects found while building them

**The pronoun bug had two independent causes.** The dictionary glosses oblique *forms* as
entries - `jų` "her", `jego` "him", `jih` "them" - which have no paradigm of their own, so
inflecting one returned the merged 53-token paradigm of every third-person pronoun and gave
the **masculine** dative for "her". Separately, nothing requested `PrepCase`, so the
longest-form tie-break emitted the `n-` form everywhere, when the page restricts it to
after a preposition. Every bare pronoun object in the app was wrong.

**A negated future lost its `ne`.** Routing "going to" through the future machinery made it
take an early return in the realisation loop, and `ne` was emitted after that point:
"I am never going to read" came out as `Ja nikogda budu čitati` - the opposite of what was
asked. `ne` is now emitted at the top of the loop, which also closes a defect this log
recorded earlier: negation was silently dropped when the negated verb was not in the
dictionary (`Ja ne blargify knigu` now keeps it).

### The validator was flagging correct output

`derive()` output - comparatives, superlatives, participles - was absent from the full-form
index, so every `večši`, `najlěpši` and `ljubjena` the engine now emits was reported as
**unvalidated**. That is worse than a gap: the validation rate is this project's primary
quality metric, and flagging the right answer teaches the reader to distrust it. The index
now includes derived headwords and their paradigms.

## Transitivity was parsed and never used (2026-10-20)

`CORRECTED`. `parse-xpos.ts` had read `transitive` since the beginning and
nothing ranked on it — the same dead-data pattern as the `(+N)` government codes
and `derive()`. English "leave" is two different Interslavic verbs and the
dictionary says which is which:

```
ostavjati   v.tr.    leave, leave behind, abandon
odhoditi    v.intr.  go away, walk away, leave, backtrack
```

"We must leave before midnight" has no direct object, so it was producing
`musimo ostavjati` — "we must abandon".

### The boolean was not enough

`transitive: has('tr.') && !has('intr.')` is also false for `v.refl.` and for
the 78 entries marked only `v.ipf.`/`v.pf.`. Only a **stated** mismatch is
evidence, so `intransitive` was added as its own field. Counts: `v.tr.` 3,411 ·
`v.intr.` 942 · `v.refl.` 606 · unmarked 78. Safe as a plain test — no entry
combines the markers, because the `/` in the notation separates aspects
(`v.tr. ipf./pf.`), never transitivity.

### `v.intr.` does not mean "takes no object"

First measurement caught this. `izběgati (+2)` "avoid" is marked **v.intr.** and
governs a genitive complement, so penalising it for having one handed the
sentence to the reflexive `stråniti sę od`:

```
Ja izběgaju pytanja.            ->  Ja straniti se ERROR2u pytanje.
```

A government code therefore exempts the verb. Measured over 126 fixtures, the
rule then changed exactly two outputs, both improvements:

```
On zabolěl se.        ->  On poranil se.          (poraniti v.tr. "hurt, wound")
musimo ostavjati …    ->  musimo izježdžati …     (a departure, not "abandon")
```

`izježdžati` is "leave (by transport)", so it is narrower than ideal; the
general `odhoditi` loses on gloss position. See the next section for the
experiment that tried to fix that.

## An experiment that was measured and reverted (2026-10-20)

`VERIFIED` as a negative result, so it is not retried. `izježdžati` is glossed
"leave **(by transport)**" — a parenthesised sense label that `normalizeGloss`
strips, so it matched bare "leave" at gloss position 0 and beat `odhoditi` at
position 2. The narrow fix tried: treat an **unsupported labelled** gloss as a
non-exact match rather than as a better positional one.

It fixed `leave` and broke "He is a doctor" into the **feminine** `lěkarka`:

```
leave-before-midnight   izježdžati  ->  odhoditi     (better)
he-is-a-doctor          doktor      ->  lěkarka      (worse)
```

Net zero, and a wrong gender is more visibly wrong than an over-specific verb.
Reverted. This is the second time a flat penalty on the sense label has been
measured and rejected — the first flipped 119 gloss keys. The label stays a
discount on frequency, as `effectiveFrequency` documents.

## The library's own error marker reached the output (2026-10-20)

`CORRECTED`, and the worst defect found that day. `@interslavic/morphology`
reports a stem it cannot handle by **returning a form containing "ERROR"**, not
by throwing — and `realize` returned `ok: true` with it:

```
stråniti sę od   ->   "stråniti sę ERROR2ų"     reported as a successful form
```

**169 entries (0.87% of the dictionary) were affected**, all multiword verb
phrases. Two causes:

1. `splitMultiword` took the **last** word as the head. That is right for a noun
   phrase (`veliky gråd`) and wrong for a verb phrase, so `na`, `do`, `dȯlžėn`
   and `råbotų` were handed to the conjugator. Fixed by passing the part of
   speech: a verb phrase inflects its first word.
2. A leading `ne` is the negation particle, not the head — `ne ljubiti`,
   `ne slušati`. Fixed by recursing past it and keeping `ne` in front.

### Why nothing caught it

The full-form index is generated from the same `paradigm()` call, so it
**contained the ERROR strings as if they were real forms** and the validator
certified them. This is the concrete reason "99.4% of output words are valid
forms" means *is a real form of something*, not *is the right form*.

Three guards now, because one was not enough: the split knows the part of
speech, `realize` refuses a form containing "ERROR", and the index never holds
one.

```
entries producing ERROR forms:  169  ->  8
```

The remaining 8 are **mis-tagged dictionary rows** — `k`, `za`, `na`, `vdesno`,
`v dveri` marked as verbs when they are prepositions or adverbs, plus `bųde`, a
form of `byti` listed as its own entry. They now fail honestly and fall back to
the citation form.

## Predicate agreement applied to a predicate noun (2026-10-20)

`CORRECTED`. Found while auditing citation-form fallbacks — 16 distinct, 15 of
them harmless (an infinitive asked for a `Number` it does not have, a nominative
pronoun for a `PrepCase`), and one real:

```
kniga <- book    wanted {"Gender":"Neut"}      kniga is FEMININE
```

"It is a good book" was copying the neuter gender of `ono` onto `kniga`. Only a
predicate **adjective** agrees with the subject; a noun's gender, number and
animacy are lexical facts about that noun. It still takes the nominative, which
is a property of the position.

The output was right **by accident**: a noun's form is not selected by gender,
and the adjective had already agreed with `kniga` in the earlier pass — an
ordering accident, not a safeguard. `Number` was equally wrong in principle:
"My favourite thing is books" would have been forced into the singular.

## Phrasal verbs, and where the line was drawn (2026-10-20)

`VERIFIED`. The dictionary glosses 1,081 verb+particle phrases — `wake up` is
`buditi sę`, `give up` is `odrěkati sę`, `burn down` is `dogarjati`, `ought to`
is `byti dȯlžėn` — and every one was translated a word at a time. This only
became implementable after the ERROR fix above, because those targets are
exactly the multiword lemmas that produced garbage.

**Only `compound:prt` is used.** A true particle is an adverb, and UD has
already decided it is not heading a prepositional phrase. That is also where the
mass of the data is: up 205 · out 203 · away 119 · off 106 · down 69.

### A verb plus a genuine preposition is deliberately excluded

Measured, not assumed. The gloss index looked like a safe gate — 11 of 12 common
non-phrasal pairs (`wait for`, `live in`, `go to`, `talk about`, `believe in`…)
have no two-word gloss at all. But one does:

```
podhoditi   v.intr.   suit, be suitable, befit, go with
```

That is the "that tie goes with the shirt" sense, and matching bare "go with"
turned "I go with him" into `Ja podhodžu njego` — "I suit him". `after` is no
safer: "look after my brother" and "go after lunch" are the same shape. English
gives the compositional reading the same syntax and the dictionary cannot
distinguish them, so the prepositional class stays word-by-word.

### Two guards removed rather than tested

The first draft filtered hits by exact gloss and excluded multiword targets.
Both were measured to earn nothing: `lookup()` is keyed by normalised gloss and
returns **0** loose matches, and only 8 multiword targets are reachable through
`compound:prt` — all of them the right answer (`look out` → `byti ostråžny`,
"be careful"; `back up` → `idti vzad`). Removing both left the output identical
across all 126 fixtures and the code shorter.

One bug was introduced and caught here: the verb branch of `splitMultiword` is
shared with the reflexive one and returned a hardcoded `reflexive: true`, so it
claimed `bazovati na` ended in a clitic. It now returns the computed value.

## The Russian source side, verified (2026-10-20)

`CORRECTED`. Russian input had **two fixtures** and no systematic check, while
everything else so far had been English-side. An audit of ordinary Russian
sentences found eleven defects. Most share one cause: **a rule stating an
INTERSLAVIC fact was gated to `lang === 'en'`**, so Russian never reached it.
There were 15 such gates; some are genuinely English-specific (articles,
do-support, phrasal particles, infinitival "to"), and these were not.

### The Russian gloss column was parsed worse than the English one

An earlier audit said so and it was still true: `ruGlosses` was a bare
`split(',')` while English had a parenthesis-aware splitter. 35 rows were cut
inside a parenthesis, producing keys nothing can match:

```
lěkaŕ   ru=врач, доктор, лекарь (разг., устар.)   ->  key "лекарь (разг."
```

**72 senses produced an unusable key and 9 entries were left with none at
all** - including `oni`, whose cell is "они (муж. род, смешанный род)" where
every comma is inside the parenthesis. So Russian **"они" ("they") could not be
looked up**, while every other personal pronoun could. Fixed by using
`parseGlosses`, which also gives the Russian column sense labels for the first
time.

### `ты` and `вы` are not the same word

The T-V rule returns the unmarked `vy` for any second person, which is right
from English - "you" marks neither number nor register, so `ty` would assert an
intimacy the source does not contain. Russian states it: `ты` is Person=2
Number=Sing, `вы` is Number=Plur. Forcing `vy` both discarded that and made the
verb plural, because `personalPronounNumber('vy')` is Plur: "Ты читаешь" came
out as "Ty čitajete".

Threading the flag by hand reached **one of six** call sites, so it lives on the
source adapter and one helper consults it.

### Russian and Interslavic govern numerals differently

The numeral phase **never ran for Russian at all**: it tested `deprel !==
'nummod'` and Russian uses the subtype `nummod:gov`. An exact deprel comparison
is wrong wherever a subtype carries the same relation, so `baseDeprel()` now
strips it - which also let the numeral agree in gender, since `AGREEING_DEPRELS`
missed `nummod:gov` too.

That exposed the real question. Russian writes "два брата" with a genitive
singular and "пять братьев" with a genitive plural; Interslavic uses the
nominative plural after 2-4 and the genitive plural after 5. **The source's case
is an artefact of the source's own numeral syntax and does not transfer**, so it
is discarded and inferred from the syntactic role - the same cascade English
uses.

Two things were measured rather than assumed here:

- UD's `nummod:gov` subtype, which means exactly "the numeral governs the case
  of its noun", looked like the right signal. **Stanza applies it
  inconsistently** - "два брата" is `nummod:gov` and "три книги" plain
  `nummod`, both in the paucal genitive - so the test is "counted by a numeral
  of 2 or more" instead. `jedin` is excluded because it agrees rather than
  governs.
- Discarding the case broke obliques: "с тремя книгами" became "s tri knigy".
  With a preposition the case the source marks is the PREPOSITION's, which does
  transfer - Russian prepositions are deliberately not planned, precisely
  because the source states the case. So the rule applies only where no
  preposition governs the noun.

### Russian omits the present copula; Interslavic writes it

"Он доктор" has no verb at all. Every example on the syntax page writes one -
"Petr jest ščestliv", "dom jest velik", "Tuto avto ne jest drago" - so it is
inserted, agreeing with the subject. The absence of a `cop` dependent IS the
present tense: a Russian past or future copula is present in the parse ("Еда
БЫЛА приготовлена"), so those are untouched.

Placement took two corrections. Keyed to the predicate's head it landed inside
the phrase ("On najlěpši jest student"); the subtree walk then swallowed the
SUBJECT, which hangs off the predicate, making the subject the leftmost word;
and the leftmost word can itself be deleted. It is now keyed to the first
SURVIVING node of the predicate phrase.

This also improved a sentence it was not aimed at. "Мы должны уйти" became "My
**jesmo** dolžni ujdti" - and the dictionary's own entry for this is `byti
dȯlžėn` ("have to, ought to"), whose first word is `byti`, so the copula
completes the lexical construction rather than merely satisfying grammar.

### Other gates that were not English-specific

| Was | Now | Cause |
|---|---|---|
| `Otvoriš okno` | `Otvori okno` / `Otvorite okno` | `Mood=Imp` is a UD feature both sources give; only the DEFAULT number was English, and Russian states it |
| `Ona skazala mně čego...` | `...že ona ustala` | the complementizer was matched on the literal lemma "that"; the source lemmas now live on the adapter (`что`) |
| `Hlapčik ktora...` | `Hlapčik ktory...` | `PronType=Rel` is a UD feature; Russian `который` carries it and was reaching the interrogative |
| `My dolžni ujdemo` | `My jesmo dolžni ujdti` | the infinitive rule required a `mark`, which is English's "to"; Russian writes a bare infinitive and states `VerbForm=Inf` |
| `Ja jesi čitaju knigu` | `Ja budu čitati knigu` | `буду` is AUX with lemma `быть`, which the English will/shall table never saw. The infinitive distinguishes it from the past copula |
| `Sama veliky dom` | `Največši dom` | Russian's analytic superlative `самый` is a separate word; Interslavic prefixes `naj-` to the comparative |

## The Russian source side, second round (2026-10-20)

`CORRECTED`. A sweep of 40 ordinary Russian sentences across aspect, voice,
mood, comparison, numerals and impersonals. The first round fixed the rules
that were gated to English; this round found defects in rules that ran but got
Russian wrong.

| Was | Now | Cause |
|---|---|---|
| `Jestli by ja jesm znal` | `Jestli byh ja znal` | `бы` is AUX with **`Mood=Cnd`**, a UD feature, and was reaching the lexical path - so the conditional `by` AND the compound-past `jesm` were both emitted |
| `On vzel nju knigu` | `On vzel jegovu knigu` | `его` is `Poss=Yes` but ranked below an oblique personal form; the dictionary has `jegov` and the pronouns page writes "jegovu knigu" |
| `U mene ne brata` | `U mene nema brata` | `нет` as a VERB is the negative existential; the interjection `ne` ("no") is far more frequent and was winning |
| `Mně zimna` | `Mně zimno` | a predicate adjective with NO subject is impersonal, and the gender fell out of a tie-break |
| `Kniga читается legko` | `Kniga čitaje se legko` | Stanza lemmatises it `читаться`, which is no dictionary headword |
| `Dom buduje rabotnikami` | `Dom buduje se rabotnikami` | a reflexive passive came out as a plain active |
| `na dva rokov` | `na dva roky` | the noun kept Russian's paucal genitive inside a prepositional phrase |
| `bystro` for "быстрее" | `bystrěje` | see below - not a Russian bug at all |
| `veče togo doma` | `veče od togo doma` | Russian marks the standard of comparison by case alone |
| `prijaje se` | `podobaje se` | `нравиться` is itself a headword, `podobati sę` |

### Two of these were not Russian bugs

**Adverbs lost their comparison entirely.** An adverb is `indeclinable`, so it
took an early return *before* the `Degree` block, and again before realisation.
A comparative is a different LEMMA (`bystro` -> `bystrěje`), not an inflected
form, which is exactly why an indeclinable can carry one. **Any English
comparative adverb - "faster", "sooner" - had the same bug**; it never surfaced
because the English fixtures only contain `more`, which works by lexical lookup
rather than derivation.

**And the inverse.** "больше" is its own lemma, so the entry it matches (`veče`,
glossed "more") is already a comparative and deriving again gave `večeje`. The
test is whether the source marks the degree on a DIFFERENT stem - "быстрее" has
the lemma `быстро` and "старше" has `старший`, so both derive. The same test
handles English "bigger" (lemma "big") against "more" (its own lemma).

### Three first attempts that measurement rejected

- **`Voice=Mid` is not a reliable signal for a reflexive.** Stanza marks
  `стала` Mid though it carries no `-ся` at all, so keying the clitic on it gave
  "Ona stala **se** lěkarem". The source FORM's own suffix is the signal.
- **Stripping `-ся` must be a FALLBACK, not a preference.** `нравиться`,
  `бояться` and `учиться` are all dictionary headwords (`podobati sę`, `bojati
  sę`, `učiti sę`); stripping first turned `нравиться` into `нравить`, which
  found the weaker `prijati`. Entries that already carry the clitic also made
  "Ja boju **se se** psa".
- **`od` fired where a preposition already governed the phrase**, giving "na dva
  **od** roky". It now applies only to a bare genitive.

### The numeral rule got simpler

The first round discarded the noun's source case and re-inferred it, with a
carve-out for prepositions. One rule replaces both: **a noun counted by a
numeral takes the NUMERAL's case.** The source marks the numeral correctly in
every position - any preposition governs the numeral, and the numeral then
governs the noun:

```
два брата        Nom + Gen.Sing   ->  dva brati        (Nom.Pl)
три книги        Acc + Gen.Sing   ->  tri knigy        (Acc.Pl)
на два года      Acc + Gen.Sing   ->  na dva roky      (Acc.Pl)
с тремя книгами  Ins + Ins        ->  s trěmi knigami  (Ins.Pl)
```

All four from one rule, where copying the noun's case gave "dvě brata", "trěh
knig" and "na dva rokov". The NUMBER still comes from the numerals page, and
for 5-and-up its case government overrides.

### A ranking change with a measured side effect

A trailing reflexive clitic no longer counts as a second word for the
single-word preference, which is what had pushed `podobati sę` below `prijati`.
That also moved "устала" from `ustala` to `umorila se` - **both** are glossed
"get tired" and the dictionary lists `устать` for both, so it is lexical
variation, not a change of meaning. Recorded because the test expectation had
to move with it.

- The inserted copula was marked `validation: 'unvalidated'`, which made the

### Two findings from surviving mutations (2026-10-21)

The 15 mutations added for the second Russian round left **2 survivors**, and
both were worth having.

**An inserted word was silently dropped before an indeclinable.** The
`insertedPrepositions` and `insertedCopulas` emission sat AFTER the
`entry.pos.indeclinable` early return in the output loop. Inserted words
precede the word they attach to, so whenever that word was a preposition or an
adverb the insertion vanished. That is why the second `od` in "starějši od mene
na dva roky" never appeared - and it masked the mutation, making the guard that
suppresses it look inert. Both blocks now run before any branch that can
`continue`. Current output is unchanged, because the guard still suppresses
that particular case; the bug was latent.

**The strip-as-fallback guard looked like dead code and is not.** Disabling it
changed nothing across 40 Russian sentences, because `нравить` and `боять` do
not exist (so stripping dead-ends anyway) and `учиться`/`учить` happen to
surface identically. Measured over the dictionary, **217 Russian reflexive
glosses resolve to one Interslavic stem whole and a DIFFERENT one stripped**:

```
мучиться  -> agonizovati ("suffer")     мучить  -> mųčiti ("torture")
иметься   -> byti                       иметь   -> iměti
беречься  -> čuvati sę ("take care")    беречь  -> ščęditi
```

So strip-first would turn "He suffers" into "he tortures himself". A fixture
pair now pins it: `on-muchitsja` -> "On agonizuje se" against
`on-muchit-sobaku` -> "On muči psa".

## Verifying Russian without a Russian speaker (2026-10-21)

`VERIFIED`. The question was whether the Russian side is as good as the
English one, with nobody available to judge Interslavic by eye. The instrument
is **mutual corroboration**: translate the same 30 meanings from English and
from Russian and compare. The two source paths share no lemma lookup, case
handling or auxiliary logic, so agreement is independent evidence and every
disagreement is a lead.

```
en:  122 words   certain 75.6%  high 13.2%  default  8.1%  guess 3.1%
ru:  119 words   certain 87.9%  high  8.6%  default  3.2%  guess 0.2%
both: 0 unvalidated forms, 0 untranslated words
```

**Russian is measurably more certain than English, and for a principled
reason**: it states case and aspect explicitly, so the engine copies where
English must infer. Its `guess` rate is 0.2% against English's 3.1%.

12 of 30 pairs are byte-identical. The other 18 break down as:

| cause | n |
|---|---|
| the two source sentences genuinely differ (my pairs are not perfectly parallel - "her brother" vs "брату") | 4 |
| both sanctioned by the grammar as equally correct (genitive of negation, `do školy`/`v školu`, imperative number, `musěti`/`byti dolžen`) | 5 |
| documented gloss asymmetry, both valid (`hlapec`/`hlapčik`, `maly`/`malenjky`) | 2 |
| English past aspect is an honest `guess` and Russian states it (`běgl`/`poběgl`, `prihodil`/`prišel`) | 2 |
| lexical variation, same gloss (`kazati`/`skazati`) | 1 |
| Russian is better (`v boljnici` over `na boljnici`; instrumental after "become") | 2 |
| English is better (`tutoj` for "this" over `toj`) | 1 |
| **real defects** | **2** |

### The two real defects it found - one on each side

**English, and it was a regression I had introduced.** "The food was prepared by
my grandmother" came out as `Jeda byla sbirati se od mojej baby` - an infinitive
reflexive where a participle belongs. The transitivity signal added earlier was
penalising every `v.tr.` candidate because the clause has no direct object - but
**a passive has no object because the patient was promoted to subject**, not
because the verb is intransitive. So `gotoviti` (v.tr.) lost to `sbirati sę`
(v.refl.). Transitivity is now only consulted in an active clause.

**Russian: a verbless clause with a non-nominal root got no copula.** "Где
станция?" has an ADV root, which predicate agreement never looks at, so it came
out as `Kde stancija?` while English - whose source supplies "is" - gave `Kde
jest stancija?`. The copula insertion moved into its own pass covering any
verbless clause, which also supplied the copula in "Этот дом больше" and in the
impersonal "Мне холодно" (`Mně jest zimno`), matching the corpus's "trěba jest"
and "Nužno jest".

Placement took four measured attempts and is worth recording, because each
earlier one looked right:

```
keyed to the predicate head        ->  On najlěpši JEST student
keyed to the phrase's first word   ->  JEST kde stancija?
shifted by one word                ->  U SUT mene dva brati
excluding every nsubj from the      ->  Kniga ktoru JEST ja čitaju interesna
  opening constituent
after the opening constituent       ->  all five correct
```

### An aspect experiment, measured and rejected

Three of the English disagreements are past aspect: `aspect.pastTelic` only
fires on a direct OBJECT, so it misses "ran into the house" and "came with a
friend", and English falls to the imperfective default at `guess`. The Russian
sources mark all three perfective, which is real evidence for the telic
reading.

Widening the cue to "a past motion verb is bounded" fixed those and two
fixtures with no gold regression - and broke the durative and habitual
readings, which are common:

```
I ran for an hour.      ->  Ja jesm POBĚGL časinu.     (should be imperfective)
She ran every morning.  ->  Ona POBĚGLA každo utro.    (should be imperfective)
```

Reverted. Doing it properly means the full telicity diagnostic - a goal phrase
bounds the event, a durative or frequency adverbial unbounds it - and half of
that produces confident wrongness in the commoner case. English past aspect
stays an honest `guess`, which is what the label is for. **Russian does not
have this problem at all, because it states aspect.**

## CORRECTED: "`kino` should be indeclinable"

Filed as a dictionary-data defect: `kino` is a borrowing, the dictionary marks
it plain `n.`, so it declined to `kinu` where van Steenbergen writes `v kino`.

That diagnosis was wrong, and the nouns page says so:

> "Borrowed international vocabulary ending in **-e, -i or -u** (f.ex. alibi,
> hobi, intervju, kafe, kakao, kliše, menju, tabu, taksi) and abbreviations are
> indeclinable."
> http://steen.free.fr/interslavic/nouns.html

`kino` ends in **-o**, so it is NOT in that class - it is a regular neuter, and
a regular neuter's accusative equals its nominative. `kino` is already the
correct accusative without any indeclinability.

The real cause was on the SOURCE side. Russian кино is indeclinable *in
Russian*: one form for all seven cases, so the parser has nothing to read and
guesses. Stanza tags "идти в кино" as `Case=Loc` when the sense is motion into,
i.e. the accusative, and `case.copy` trusted that guess with `certain`
confidence.

VERIFIED fix: `fromSource` in `resolvers/case.ts` refuses to copy a case from a
token marked `InflClass=Ind`. Nothing is lost - the form carried no case - and
the cascade then reaches the preposition's own government, where a motion verb
with a two-case preposition already selects the accusative on a cited rule.

Lesson worth keeping: `copyCase` is only sound where the source form actually
encodes a case. A language that marks case still has words that do not.

## VERIFIED: an empty `type` cell behaves like tier 2, not tier 3

`type` is the dictionary's intelligibility tier (official schema
`steenbergen.xsd`): 1 universally intelligible, 2 regionally, 3 single
languages only, 4 Church-Slavonic-derived, 5 a coined neologism, 9 unclear.
Lower is better and `score()` adds it directly, so the default for an empty
cell is a real ranking decision - it covers 799 entries and decides 307
contested gloss keys.

It defaulted to 3. That asserts something the dictionary never said, and lands
those rows in a bucket holding only 469 rows (2.4%), two points behind the 74%
that are tier 1.

The dictionary answers the question itself. Its separate `intelligibility`
column - populated on 19,096 of 19,100 rows, and previously unread - gives a
per-language `+`/`-` verdict. Counting the languages each row marks `+`:

| `type`  | rows   | mean languages marked `+` |
|---------|--------|---------------------------|
| 1       | 14,168 | 7.04                      |
| (empty) | 799    | **5.07**                  |
| 2       | 3,493  | **4.97**                  |
| 3       | 469    | 3.94                      |
| 4       | 30     | 2.77                      |
| 5       | 138    | 4.07                      |

An untyped row is indistinguishable from a tier-2 row on the dictionary's own
measure of exactly the property `type` encodes, and clearly above tier 3. So
the default is 2, read off the data rather than chosen.

Effect: 0 of the 220 fixtures change and the gold score is unmoved, so this is
not an accuracy claim. It is not inert either - re-ranking all 6,355 contested
gloss keys with tier 2 treated as tier 3 moves the top choice on 163 of them
(an upper bound, since it bumps every tier-2 row and not only the untyped

`akomodacija` -> `pravka` for "adjustment", `avarija` -> `nesgoda` for

Built, each from a source:

- **Russian names in Latin.** The flavourisation page's East Slavic row (я ю йо/ьо

  stays in Cyrillic, not guessed.

  has toj, kto 2, togo, kto 5, tyh, kto 3, ti, kto 2.

- **English names that are also words** ("Trump" -> kozyr): tried and reverted. A

- **"let me + verb":** the only evidence is one Tatoeba sentence ("Daj mi znati"), with

- **Causative "make X do":** one example ("pričiniti, že ... sojme"), and the clause

## VERIFIED: asking someone's name (2026-10-25)

"What is your name" was compared with another tool's "Kak se ty
zoveš?". Ours was "Čto jest vaše ime".

- **"vaše" (polite you) is right** for a stranger: "vy is a universal second person
  pronoun for both numbers, whereas the second person singular ty is used only for
  addressing friends, relatives and children" (pronouns page). The other tool's "ty"
  is the familiar form.
- **"čto" was a calque.** Slavic asks a name with "how": Russian "Как ваше имя?",
  Croatian "Kako je vaše ime?", Czech "Jak se jmenujete?", Tatoeba's Interslavic "kak
  on se imenuje" (12987096). Our own Russian path already gave "Kak jest vaše ime?".
  Now "What is your name?" is "Kak jest vaše ime?"; only a name - "What is your
  address?" stays "Čto jest vaš adres?".
- **Found on the way: "What is this/that?"** was "Čto jest tutoj/toj?", masculine.
  Tatoeba writes "Čto jest to?" for "What's that?" (12984803), the neuter
  presentational "to" the engine already used before a noun. Now "Čto jest to?" and
  "Kto jest to?".

Left as is: with no question mark typed, none is added - the output keeps the
source's punctuation. "Kak se zovete?" (reflexive verb) is the other natural way to
ask; "Kak jest vaše ime?" mirrors the English and the Russian it is translated from.

### Then: what was fixed, and what was left on purpose

Fixed (each with a test, and a mutation the test kills):

- **train station** -> "Kde jest želěznična stancija?", and it inflects: "do
  želězničnoj stancije". A noun + noun compound the dictionary glosses as one
  adjective + noun phrase is used as its two entries, so agreement inflects both
  (the one-lemma entry inflected only "stancija"). Separately, a noun modifier with
  no adjective now ranks as the noun it is: "train ticket" took the verb
  `trenovati` and now takes `pojezd`. "bus stop" became "avtobusna postojka" (it
  was "avtobusny zajezd"). No other fixture or gold sentence changed.
- **Interslavic** -> "Medžuslovjansky jest moja nova obsesija" (Tatoeba 12994632).
  A source noun that becomes an adjective - a language's name - takes the gender
  its headword names, like every other standalone adjective.
- **one auxiliary for two verbs** -> "Ja budu čitati i pisati", "Ja byh čital i

  writes" stays two clauses.

Left, with the reason:

- **"stayed" -> ostaval (Tatoeba: ostal).** An English simple past with no object
  and no goal falls to the last-resort imperfective, shown as a guess. A wider
  "simple past is perfective" rule was tried before and broke other sentences;
  changing it needs a measured study, not one verb.
- **"at school" -> na školě (Tatoeba: v školě).** The prepositions page gives "na

- **"I speak Interslavic" -> rěku.** The dictionary lists `rěkti` "speak, say"
  before `govoriti` "say, speak, talk" and as more frequent; the dictionary outranks

## Aspect, measured as a class rather than sentence by sentence

A scan of every English fixture found 102 verbs that fall to the last-resort
imperfective (`aspect.default`). About 75 are right (no perfective partner,
durative, habitual, modal); about 25 are wrong, in four groups, all from one
cause - the perfective rules fired only on a PAST verb with a noun object or
a goal:

1. a particle that states the result ("burned down", "ran away");
2. a verb whose meaning is a result, with no noun object ("stayed", "died",
   "succeeded", "agreed that...");
3. infinitives and commands, which never reached a perfective rule
   ("could not find", "open the window");
4. passive participles ("was prepared", "is broken").

### Group 1 fixed: particles

`aspect.pastParticle`: away, down, off, up - and "out" only on a verb of
motion, because "the Sun shined out" is a beginning (northwind.html,
"načelo blěskati"). "away" and "back" are often tagged `advmod`, so the
phrasal-verb lookup now reads them too ("run away" -> `uběgti`).

```
The house burned down.   Dom dogarjal.        ->  Dom dogorěl.
They ran away.           Oni běgli proč.      ->  Oni uběgli.
He gave up.                                   ->  On odrěkl se.
She sat down.                                 ->  Ona usědla.
The children went out.                        ->  Děti izšli.
He was running away. / He always gave up. / She sits down.   (stay imperfective)
```

No other fixture changed.

### Group 2 fixed: verbs that name a result

`aspect.pastResult`. English shows nothing, but the dictionary's aspect pairs
do. The verbs page: unprefixed verbs are imperfective, a prefix makes the
perfective (pisati > napisati), and only a perfective that is itself the
starting point gets a secondary imperfective (priznati > priznavati). So a
verb whose perfectives are NOT built on its imperfectives names a result
(ostati > ostavati, uspěti > uspěvati, umrěti > umirati); one whose
perfective is a prefix on the imperfective names an activity. Perfectives in
-nųti (kriknųti) are one instance of an activity and are set aside.

Checked on 50 verbs, 20 of each kind, before use: all 50 as expected.

```
He stayed in the house.   On ostaval v domu.  ->  On ostal v domu.   (Tatoeba 13467063)
He died last year.        On umiral ...       ->  On umrl ...
She succeeded.            Ona uspěvala.       ->  Ona uspěla.
They agreed that...       soglašali se        ->  soglasili se
We arrived yesterday.     dohodili            ->  došli
UDHR "endowed"            obdarjani           ->  obdarjeni          (his text)
thought / knew / lived / ran for an hour / waited for an hour   (unchanged, imperfective)
```

Left, and why: "say", "lose" and "understand" read as activities, because
`skazati`, `izgubiti` and `sråzuměti` are built on `kazati`, `gubiti` and
`råzuměti` - so "He said that..." stays `govoril`. North Wind "a traveler
came along" became `prišel` where his text has `prohodil` ("was passing");
it was wrong before too (`prihodil`), and the gold score is unchanged (31/58).

### Group 3 fixed: one bounded act wanted, possible or asked for

`aspect.singleAct`. An infinitive under a verb or modal, or a positive
command, bounded by an object or a completive particle, is perfective: his
"ne mogl najdti" (g13), Tatoeba "Ja hočem kupiti jabloka", "On probuje najdti
svoju olovku", "Otvori vse magaziny".

```
Father could not find his keys.  nahoditi      ->  najdti          (his g13)
I want to buy a car.             kupovati      ->  kupiti
Can you help me?                 pomagati      ->  pomogti
Open the window, please.         Otvarjajte    ->  Otvorite
Help me! / Read the book.        Pomagajte / Čitajte -> Pomožite / Pročitajte
Please close the door.           zaključajte ("lock") -> zatvorite
```

Left out, each with its evidence: "will" (the page shows only "budu dělati";
Tatoeba "on bude pomagati"); phase and liking verbs (Babel "prěstali
budovati"); purpose clauses (his "že by fotografovali"); negative commands
("Ne otvarjajte"). A bare plural object leaves the act open - "He could read
books" stays `mogl čitati`, the ability reading gold.test.ts warned about;
"eat apples" `jesti`, "eat the apples" `sjesti`. The result-verb test is NOT
used here: on "should act towards one another", a general norm, it gave
"postupiti" against his UDHR "imajut postupati", so it was taken out.

### Group 4 fixed: the past passive

No new rule: the subject of a passive is the object of the active, so the
object rule now reads a past "be" + participle with its subject. The present
passive stays imperfective, as the page gives it ("ja jesm nesomy").

```
The food was prepared by my grandmother.  gotovjena -> prigotovjena
The letter was written by him.            pisano    -> napisano
The book is read by the woman.            čitana    (unchanged)
```

### Where the four groups leave it

21 of the ~25 wrong verbs in the first scan are fixed; no gold or fixture
sentence got worse (gold 31/58 unchanged). Still open, on purpose or as a
different problem:

- "I will come", "We must leave" (no object): the future and an unbounded
  infinitive are left to the default for the reasons above.
- "He said that..." / "She told me that...": `skazati` is built on `kazati`,
  so the morphology reads "say" and "tell" as activities.
- "The pizza is made", "One of them is broken": present, so imperfective by
  the page's rule; a resultative state would want the perfective participle.
- Found while checking, not aspect: "She began to write" takes the reflexive
  `počęti sę` ("počela se pisati"); "letters" -> `pisemnosti`; the agent of
  "written by him" is "od strany njego" where the page gives plain "od".

## "at": v inside a building, na elsewhere

The cause: "at" has one locative candidate in the government table, `na`
("on, at"), so EVERY "at + place" came out na - "na školě", "na boljnici",
"na hotelu", "na restoranu". Frequency cannot separate "na stanciji" (right)
from "na školě" (wrong).

Corpus evidence per noun does not exist in quantity: the Tatoeba isv export
is 1,605 sentences (1-4 examples per noun), van Steenbergen's texts fewer,
and the Wikipedia search returned 0-3 hits per phrase before rate-limiting.
What decides it is the grammar page's own principle: Interslavic "is entirely
based on forms common to the Slavic languages, and when no common forms
exist, on majority solutions". So:

- `na` stays the default for "at", as the prepositions page lists it - right
  for work, stations, streets, markets, events, "the end of";
- a noun listed in `rules/data/at-inside.json` takes `v`: buildings and
  institutions where ru, pl, cs, hr and bg all say "in" (в школе, w szkole,
  ve škole, u školi, в училище), each with those five forms recorded;
- split nouns are left out ("university": ru/bg в, pl/cs/hr na); a compound
  ("post office", "na pošti") is not looked up as its head noun.

```
She is at school.           na školě     ->  v školě      (lesson's Tatoeba 12999978)
I was at the hospital.      na boljnici  ->  v boljnici
We ate at the restaurant.   na restoranu ->  v restoranu
The man works at the house. na domu      ->  v domu
He is at work / at the station / at the concert / at the market   na (unchanged)
```

No other fixture changed. The Prepositions lesson's "Ona jest v školě" now
has a Try-it link: the translator agrees with the lesson.

## "-ing" nouns the dictionary lacks

The site's own tagline came out "...pokazyvaje svoje **reasoning** dlja vsakogo slova":
"reasoning" is not a dictionary noun, and an unknown noun was passed through in
English. The class: any English "-ing" noun the dictionary does not list (of 7 tried,
reasoning, cooking and reading failed; swimming, thinking and understanding are listed).

The grammar states the rule: "The act itself is represented by the verbal noun
(gerund), ending on -nje: dělati > dělanje" (word_formation.html; verbs.html on
-nje). Now such a noun is the verbal noun of its verb, imperfective preferred:

```
shows its reasoning     reasoning   ->  razumovanje   (råzumovati "reason")
Her cooking is excellent  Jej cooking jest odličny  ->  Jej kuhanje jest odlično
The reading of this book  Reading ... vzel          ->  Čitanje ... vzelo
```

Only when the noun finds nothing; no existing fixture changed. Noticed, not
fixed: "Thank you for your understanding" gives "Blagodarju vas dlja ..." where
thanks take "za"; "took a week" gives "vzelo" (take) where duration is "trajati".

## "for" as za, and "take" + a span of time

Both were classes, not sentences.

**"for".** The dictionary has two: `dlja` (+gen) "for" and `za` (+acc) "for, because
of, due to, in exchange for, in favour of". Ranking always chose `dlja`, so every
exchange / reason / support "for" was wrong: "platil dlja biletov", "glasovali dlja
njego", "odgovorny dlja projekta", "Blagodarju vas dlja". The deciding word picks it,
so these went into the existing governed-preposition table, each attested:
thank/thanks ("hvala za", Wp/isv), pay ("platil za", Wp/isv), vote ("glasovali za",
Wp/isv), responsible ("odgovorny za", Wp/isv), prize/award ("Nagrada za", Wp/isv),
fight and die ("borju se za", "umrli za", Tatoeba). The table now also takes an
adjective or noun as the deciding word. `dlja` stays the default for whom/what
something is for ("dar jest dlja vas", "dobro dlja vašego zdravja") - also how van
Steenbergen and Tatoeba use it ("idealny jezyk dlja prěvoda").

**"take" + time.** "took three days", "it takes an hour" mean "last" (`trvati`), not
`vzeti`: "Putovanje vzelo tri dnje" -> "Putovanje trvalo tri dnje". It also exposed
an aspect gap: a span of time parsed as the OBJECT counted as a bounded object
(perfective "potrvalo"). New `aspect.duration`: a time-span object says how long it
went on - imperfective, like "ran for an hour".

No existing fixture changed. Noticed: "won a prize" gives `izigral` (win a game)
where `dobyl` fits; "It takes an hour" keeps "Ono" for the dummy "it".
