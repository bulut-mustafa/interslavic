## A second engine to check against (2026-10-18)

Until now every form we emit was generated by one library and checked against a
full-form index built by **that same library** - which cannot catch a paradigm that is
wrong in the same way twice. `docs/archive/morphology-coverage.md` admitted this: the audit
"validated the library largely against itself, with only four forms hand-derived".

There is now an independent one. **`@interslavic/utils` 3.4.4 (MIT)** is the inflection
and transliteration engine behind **interslavic-dictionary.com** - so it is literally the
table a user sees when they check our output against the dictionary site.

Two honest caveats, both load-bearing:

- It is **deprecated on npm**: *"Superseded by @interslavic/morphology, @interslavic/translit,
  @interslavic/conllu, @interslavic/levenshtein, @interslavic/stemmer"*. The package we
  depend on is its designated successor, not an unproven alternative.
- Both come from the same authors, so they are **not fully independent**. They are
  independent *implementations*, which is enough to catch a coding error, and not enough
  to catch a shared misreading of the grammar. Tier-1 pages still decide.

It is used as a **tier-3 oracle only**: where it disagrees with the normative pages, the
pages win, and the disagreement is written down here.

### Orthography: all four variants now byte-identical to the reference

`packages/eval/scripts/diff-orthography.ts` renders every generated form in all four
orthographies and compares against the official transliterator.

| Variant | Before | After |
|---|---|---|
| standard | **0** / 348,707 | 0 |
| cyrillic | 8,097 / 348,707 | **0** |
| etymological | 12,532 / 348,707 | **0** mismatched, 12,532 *sanctioned variants* |
| simplified | no official tag to compare against | confirmed = standard with jat folded |

**The Cyrillic defect was real, and it was ours.** We wrote `pisańje` as `писање`; the
orthography page calls `писанје` the ideal and `писање` only a *"valid alternative"*,
allowed because *"automated transliteration is unable to predict whether nj should become
њ or нј"*. The etymological spelling **is** that prediction - `ń` marks precisely the case
where the `j` begins a suffix - so we were taking a fallback we are not entitled to. Now
fixed for all 8,097 forms, with the page's second two-sound case (a `j` after a Latin or
Greek prefix: `konjunktura` → `конјунктура`) handled by the same rule.

The reference implementation carries that prefix list too (`konjug`, `konjun`, `injek`)
and is **missing `panjev`**, which the page names explicitly. So `panjevrějsky` →
`панјеврєјскы` is a case where we are right and the dictionary site is wrong.

The 12,532 etymological differences are **not defects**: the page says t́ and d́
*"may be written with a haček as well: ť and ď [...] Likewise, ĺ can be written as ľ"*.
We emit the haček forms because they are single codepoints, which keeps output font-safe
and byte-stable. Recorded as a choice, not a divergence.

`simplified` is not ours to invent either, and we did not: *"the best alternative is
Latin e / Cyrillic е. This is a legitimate simplification"*. The same page offers a second
one we deliberately do **not** apply - `y` → `i`, addressed to those "targeting a
predominantly South Slavic audience" rather than to everyone.

### Paradigms: the forms were already right

`packages/eval/scripts/diff-paradigms.ts` compares **the form the engine would emit** for
a feature slot - `realize()` output, not a raw paradigm dump, so variant preference and
syncretism tie-breaks are included - against the same slot in the reference.

| Class | Slots | Agreement |
|---|---|---|
| noun (7 cases × 2 numbers) | 122,878 | **99.19%** |
| verb, present tense | 26,118 | **100.00%** |
| verb, l-participle | 4,353 | **100.00%** |

This answers the question that started the audit: **our divergence from other tools is not
in the forms.**

### The one real defect it found: plurale tantum never inflected

The library tags `dveri` "door", `usta`, `nožnicy` with `Number=Ptan`, which matches
neither `Sing` nor `Plur`. `selectForm` matched features exactly, so **all 155
plurale-tantum entries failed to inflect in every case** and silently fell back to the
citation form. A plurale tantum has no number to choose between, so a requested `Number`
is not a constraint it can fail; `selectForm` now says so. 854 slots recovered.

**The full-form validator could not have caught this**, for the same reason it missed
`Kak ty dělaješ?`: the citation form it fell back to is a real word.

### The remaining 136 noun slots: we are right, the reference is wrong

136 slots across **17 lemmas**, every one of them a word where the dictionary states
explicit principal parts - `Ljviv (Ljvova)`, `plȯť (plti)`, `dȯći (dȯćere)`.

Checked before concluding anything: `declensionNoun` returns **identical output with and
without the `addition` argument**, so the reference ignores the dictionary's own editorial
override. We feed it to the morphology library as principal parts, which is why we differ.

Confirmed at tier 1 for `dȯći`, from the noun page: *"feminine nouns on -i/-er-,
containing only two nouns: mati 'mother' and doči 'daughter'"*, and *"mati is inflected
like kost: gen./dat. materi"*. So gen.sg is `dočeri` - **ours** - and not the reference's
`doče`. `dno` Voc.Sg is a second clear case: we give `dno`, the reference gives
`den / dnju` for the vocative of a neuter noun.

## Running the mutation audit in slices (2026-10-18)

### The audit now runs in slices, because it could not run at all

The audit is ~119 suite executions, and this machine killed it twice for memory pressure -
once with the default worker pool, once with a single fork. Both times the `EXIT` trap did
its job; the first kill still left one mutation applied in `split-lemmas.ts` (`if (false)`
where `if (reflexive)` belongs), and the suite caught it on the next run.

Two changes make the gate usable rather than aspirational, and neither weakens it:

- `TEST_CMD` overrides the test command, so the same tests can run in a smaller worker pool.
  A single-threaded *threads* pool turned out to be ~3x faster than forks (20s vs 70s per
  suite run) and lighter on memory:
  `TEST_CMD="npx vitest run --silent --pool=threads --poolOptions.threads.singleThread=true"`
- `FROM`/`TO` run a slice by 1-based mutation index, so the audit can be completed in
  chunks. Each chunk still saves and restores every file it touches, and the summary
  **prints "this is a PARTIAL run"** whenever anything was skipped, so a slice cannot be
  mistaken for a full pass.

Every mutation added in this round was also verified individually against the test file
that should catch it, before being added to the script:

| Group | Mutations | Result |
|---|---|---|
| Cyrillic two-sound rule | 4 | all killed |
| Plurale tantum relaxation | 1 | killed |
| Verb government | 3 | all killed |
| Coordination | 4 | all killed |
| Modal verbs | 6 | all killed |
| Reflexives and `svoj` | 7 | 6 killed, **1 survived** and exposed a vacuous assertion |
| Plurale tantum numeral | 2 | all killed |
| Word sense and female equivalents | 7 | 6 killed, **1 survived** and exposed a second weak test |

The script grew from 101 to 135 mutations. Two of the new ones survived on first run and
both found a real hole in a test rather than in the engine:

1. the `svoj` negative test compared case-sensitively against a sentence-initial word;
2. replacing the female-equivalent derivation check with a bare `endsWith('ka')` passed,
   because every negative case in the test happened not to end in `-ka`. The discriminating
   case is `měrka` - "ruler" the measuring stick, which is nobody's female equivalent and
   does end in `-ka`.

### The audit's own maintenance hazard

**Three pre-existing mutations went stale in this one session**, each because a refactor
moved the line its `sed` pattern matched:

| Mutation | Broken by |
|---|---|
| `cyrillic skips the standard fold` | `toCyrillic` gaining the two-sound pre-pass |
| `government read off the wrong verb` | the conjunct-propagation rewrite of that loop |
| `frequency tie-break removed` / `frequency sorted ascending` | frequency becoming `effectiveFrequency` |

This is a real property of a `sed`-based audit, not an accident, and it cuts the right way:
the script distinguishes **"MUTATION DID NOT APPLY (pattern not found)"** from a true
survivor and counts it as a survivor anyway. A stale mutation therefore shows up as a
failure rather than as silent green, which is exactly what should happen - but it means
**every refactor of a line a mutation targets needs the mutation updated in the same
change**, and the audit has to be re-run after refactors, not only after behaviour changes.

One **pre-existing mutation had to be repaired**: `"cyrillic skips the standard fold"` no
longer matched after `toCyrillic` changed, and the script counts a mutation whose pattern
does not match as a SURVIVOR - so leaving it would have reported a false alarm while
silently covering nothing.

## Test suite integrity

A test is only real if it fails when the behaviour breaks. So the suite was audited by
**mutation testing** (`scripts/mutation-audit.sh`): deliberately introduce a bug, confirm
the suite catches it. A surviving mutation means fake coverage.

| Run | Killed | Survived |
|---|---|---|
| First audit | 25 | 7 |
| After fixes | 35 | 0 |
| After prepositions + numerals | 52 | 0 |
| After the parser service | 68 | 0 |
| After the recheck before the web UI | **75** | **0** |

Run it yourself: `bash scripts/mutation-audit.sh`

### Defects the audit found in our own code

1. **`byti` 3sg returned `je` instead of `jest`.** The variant-preference list was
   `['Long','Short']`, so when no `Long` form existed it fell through to `Short`. Surveying
   the lexicon showed three competing patterns — `Long+Short` (1320 slots), `-+Athematic`
   (826), `-+Short` (382) — so the unmarked form must be preferred *first*. The old list
   mishandled 1,208 of 2,528 competing slots. Fixed; cross-checked against the dictionary's
   own principal parts (`byti → jest`, `dati → da`, `jesti → je`, `věděti → vě`).
2. **Invisible combining characters in source.** Unicode escape sequences (written in
   source as backslash-u-0-3-0-0) had been written as
   literal combining characters inside a regex. It worked by accident. Rewritten with
   visible escapes.
3. **Dead code.** An explicit yo→ye replacement was redundant: `normalize('NFD')` plus
   diacritic-stripping already maps `самолёт` and `самолет` to the same key. Removed.
4. **Prepositions were asked to inflect.** Indeclinables were given a `Number` feature,
   failed to inflect, and were wrongly reported `unvalidated`. They now bypass realisation.
5. **Numeral government ran after agreement**, so a numeral agreed with its noun's stale
   pre-government features — "I see one house" produced `jedne dom` instead of `jedin dom`.
   Government now precedes agreement.
6. **Numeral government forced the nominative.** The grammar's "nominative singular after 1"
   describes the citation form; "I see one house" is accusative. Only 5-and-up imposes a
   case now; 1 and 2-4 fix the number alone.
7. **Unreachable tie-break.** Across 66,697 feature slots, **0** stay ambiguous after
   variant preference, so the final tie-break never ran in production. Rather than leaving
   untested dead code, the logic was extracted into the pure exported `selectForm()` and
   tested with synthetic ties.

## VERIFIED: full mutation audit against the final code (2026-10-25)

All 316 mutations were run against the code at a8ec0e4, in chunks of 40 on 2 workers.
The tests caught 313 and 3 got through. Each one was a missing test, and one of them hid a real defect:

| survivor | why no test caught it | resolution |
|---|---|---|
| `collective: children not covered` | English "children" now reaches the plural-only `děti` by its form, so only Russian still reaches `dětę` (Stanza lemma for "детей" is `ребенок`) | Russian fixture "Я вижу четырёх детей.", test asserts the "četvero" note |
| `past gender ignores pronoun feats` | no fixture had an untranslated subject whose gender is marked in the source | "Зульфия спала." -> "Зульфия spala." |
| `predicate skips untranslated subject` | same gap, and it hid a **defect**: the predicate ignored the source's Gender and defaulted to masculine, "Зульфия jest ščestlivy" | the predicate now reads the source's gender, as the l-participle did: "Зульфия jest ščestliva", "Рустам jest ščestlivy" |

All four fixtures are live Stanza parses. Each of the 3 mutations, plus a new
one for the fix (`predicate ignores source gender`), was rerun and caught. The audit
now has 317 mutations, 0 stale. 431 tests pass, and typecheck is clean.

Known and left alone: an unknown Russian name stays in Cyrillic. The orthography page
defines Latin<->Cyrillic only for Interslavic's own letters, and gives no mapping for
Russian-only letters (я, ю, щ, ь, ъ, э, ё, й), so a transliteration would be invented.

## 2026-11-22 · Pipeline audit and a real-world score

A full pass over parser, server, engine and web, looking for places where the code
disagreed with itself or lost data. Branch `translator-quality`.

**CORRECTED - plumbing.**
- With no final mark, the parser undid its appended "." on every sentence, so
  "Что ты делаешь? Я читаю" lost its "?" (`app.py`, `to_conllu.py`).
- `/api/translate` sent all lines as one string, and Stanza reads one newline as
  a space: two typed lines became one sentence. Each line is now parsed on its own
  and marked `breakAfter`.
- The web made two requests, so two parses, for the two scripts. Now it makes one.
- A bare "ся" crashed the Ukrainian lemma check. One bad subtitle line failed the
  whole batch.
- Parser and engine failures came back as 400 with developer text. They are now
  503 and 500, worded for a visitor.

**CORRECTED - the engine against its own rules** (one fixture test each in
`packages/engine/test/robustness.test.ts`):
- A completive cue made an English present perfective ("srazuměju").
- A Russian zero copula ignored subjects joined by "and" ("jest lěkari").
- A second purpose clause copied the first one's agreement.
- "not tender" switched to ni- ("nižny").
- "её" (lemmatised "ее") never reached the curated `jejin`.
- Digits counted as untranslated, and "1.5" governed as 15.
- A final mark behind a closing quote was lost.
- Verb government ignored a chosen phrasal verb.
- Ties were broken by the machine's locale.

**Measured.** `packages/eval/scripts/score-tatoeba.ts` scores 150 English and 150
Russian Tatoeba sentences against their attested Interslavic. The parses are frozen,
and the sample is split into a tune half and a held-out half. Baseline (old parser
and engine) → this pass:

| | tune exact | tune word F1 | held exact | held word F1 |
|---|---|---|---|---|
| en | 12 → 13 | .602 → .604 | 19 → 19 | .603 → .603 |
| ru | 24 → 26 | .738 → .749 | 30 → 29 | .796 → .792 |

The one held-out loss is "jej psa" → "jejinogo psa". The pronouns page gives both
forms, and the curated entry picks the declinable one.

**CORRECTED - found by the tune half.**
- Russian verbs with an invented lemma (лжёт → "листить", шёл → "ийти") now take
  simplemma's infinitive. Re-parsing all 700 fixtures changed exactly three lemmas,
  all three corrections.
- A Russian 1pl under a conjunction is a future, not "let us". Steenbergen's Babel
  text gives "da byhmo ne razprostranili se".
- A reflexive pronoun elsewhere in the sentence no longer removes a verb's own `se`.
- A headword note ("naskakati (na)") is no longer written out.
- A verb whose only candidates are nouns is now kept and flagged ("gospodiceju" for
  "miss").
- Counting takes the citation "dva" (numerals page), not "(dvě)".

**Seen and left, with the reason.**
- "look for": verb + preposition pairs stay out of the phrasal-verb rule, which
  explains why.
- "Tom" as an object stays undeclined. English gives no person/place tag, so
  telling them apart needs name recognition.
- Stanza misparses "Fire burns" and "Испания, Швеция и Япония — монархии".
- "Tom caved" and "I miss the army" are dictionary gaps; no word is invented.
- Unknown verbs keep no `jesm`/`se`, because a kept source word with an Interslavic
  auxiliary is not better.
- "you" stays `vy`, where most Tatoeba references write `ty`. That is the adapter's
  documented choice.

## 2026-11-22 · Word choice: what the tune half says, and what changed

**Method.** An audit script used the lexicon's `analyzeText` to turn every human
reference back into lemmas. Then, for each content word we wrote, it asked: is our lemma
in the reference? If not, was the reference's lemma among our candidates? On the en tune
half: 573 right, 164 where the reference's word was a candidate, 121 with no candidate.

**What the 164 are.**
- Most are not errors:
  - spelling variants of one entry (hotěti/htěti, iměti/imati, kogda/kogdy);
  - valid synonyms where our word is the more widely understood one (mlady vs juny,
    vojin vs vojak);
  - aspect.
- Tested and REJECTED:
  - Weighting the dictionary's intelligibility column more strongly: 8 weights, none
    significant, and most lowered exact match.
  - Removing the English "no object, so not transitive" penalty: +0.22 [−0.10, 0.56],
    not significant.
- **Aspect after modals ("mogu pomogti"), in negated pasts and in imperatives:**
  - The grammar pages are silent; their few examples use perfectives ("ne mogl
    najdti", "Nikto ne prijehal").
  - A corpus count (Steenbergen's texts, about 57,700 words, and the Interslavic
    Wikipedia dump of 2026-11-01, 1,525 pages) finds both aspects, with counts of 0-15
    per construction: too few for a rule.
  - Steenbergen writes `budu` + imperfective in 53 of 54 futures, as we do. Unchanged.
- **jedati vs jesti:** the attested form is jedati ("Ovca jedaje vse", Maly princ;
  about 20 jedati forms on Wikipedia against 1 jesti). Unchanged.

**CORRECTED.**
- English "no" before a noun is `nijedin`, not a second `ne`. Source: the pronouns
  page and the syntax page's "nijednu knigu".
- A "not" that a whole dictionary phrase absorbed ("not good" → nedobry) is no
  longer negated again.
- There were 6 doubled negations in the 1,212 sentences. Tune: exactly the 3 intended
  sentences changed, with chrF −0.00 [−0.02, 0.03], because the references paraphrase
  them.

**Conclusion.** The ranker's choices among the dictionary's own words are mostly
defensible, so the gap to the references is largely style. The larger remaining errors
are in the other 121 words: idioms ("Shut up"), parser misreads ("Fire burns", "The
cat's sleeping") and dictionary gaps.

## 2026-11-22 · Parser trial: Stanza `default_accurate`

**Setup.** Stanza 1.15's accurate packages (English POS and parsing on ELECTRA-large,
Russian on RuBERT; Ukrainian's accurate package is the default one) re-parsed the
1,212 sample sentences through the repo's own `to_conllu`, so the terminator handling
and the lemma repairs were unchanged.
- **Control:** the default package, run in the same scratch environment, reproduced
  all 1,212 frozen parses exactly.
- **Scoring:** `score-tatoeba.ts --parses <dir>`, against the current engine on the
  default parses.

**Results.**

| | chrF change, 95% interval | sentences better / worse |
|---|---|---|
| en held | +0.34 [0.09, 0.61], significant | 21 / 3 |
| en tune | +0.53 [−0.15, 1.23] | 16 / 9 |
| ru held | +0.54 [−0.04, 1.32] | 4 / 1 |
| ru tune | −0.21 [−1.93, 1.18] | 4 / 3 |

- **English gains:** short sentences the default model misreads, e.g. "Fire burns"
  ("Požarne opekliny" → "Ogonj gori"), "Women like cats", "The cat's sleeping",
  "Tom's gay".
- **Russian losses:** the engine's Russian rules expect the default model's trees.
  "Том лидер" lost its inserted copula ("Tom lider") and "шёл" came through in
  Cyrillic.

**Cost (English, on a laptop CPU).**
- Load: 2.9 s → 8.5 s.
- Per sentence: 69 ms → 676 ms (about 10×).
- Peak memory: 662 MB → 1,890 MB.
- The model also needs the `transformers` library and about 1.3 GB of ELECTRA
  weights in the image.
- Production peaks at about 2.1 GB of 4 GiB, so it would reach about 3.3 GB.

**Decision (2026-11-23): adopted for English POS only.** `app.py` `ENGLISH` uses
`combined_electra-large` for tagging; parsing, lemma and Russian stay on the default
packages (the transformer parser was 1.5x slower again for little gain, and Russian's
accurate model broke the engine's Russian rules). `/parse-many` batches lines: 157 → 48
ms/sentence, identical output on 200/200 sentences. Fixtures were re-frozen with the
production pipeline: 2 of 705 translations changed (g11 better; "I read a book every
night" now reads as present). `fixtures:check` shows 140 files differing, but all are
XPOS-only (the new tagger's tag names) except the hand-written Russian
`synthetic-byt-aux-participle`, which is meant to differ.

**Memory (measured on the laptop).** The service with en+ru+uk loaded: 2.8 GB footprint,
3.3 GB peak. Cloud Run has 4 GiB, so the margin is about 0.7 GB. Raise the limit before
deploy if the peak grows.

**Safety rule for this 8 GB laptop.** One accurate English pipeline is about 3.4 GB. Never
load two at once, and never run it over the whole Tatoeba set in one call. A trial that did
both (int8 quantisation) filled memory and restarted the machine on 2026-11-23. It was not
repeated; run such trials on a small sample with a memory watchdog.
